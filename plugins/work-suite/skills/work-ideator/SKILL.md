# Work Ideator

Use this only when ambiguity would change implementation.

1. Read the request and the code, product, or evidence it touches.
2. Name the reader/user outcome, the current behavior, and the constraint that matters.
3. Apply Ponytail's ladder: does this need to exist, already exist, or reduce to a native/stdlib/current dependency?
4. Compare only materially different shapes. Reject speculative flexibility.
5. Pick the smallest complete shape and state what it deliberately does not do.

Output a short planner handoff: problem, evidence, chosen shape, thin slice, non-goals, and any true open decision. Do not create a workshop, option catalog, or planning document when the answer is already clear.
